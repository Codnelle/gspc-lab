# Contributing to ReportKit

Thanks for helping! A few rules keep reviews fast.

1. **One issue, one branch.** Name it `fix/<issue-number>-<short-topic>`,
   for example `fix/1-empty-export`.
2. **Comment before you code.** Say you are working on an issue and wait for a
   maintainer to reply before opening a pull request.
3. **Tests must pass.** Run `pytest -q` before you push. A bug fix needs a test
   that fails without the fix.
4. **Commit messages.** Imperative subject line ("Fix crash on empty export"),
   then a blank line and why. End with `Fixes #<issue-number>`.
5. **Keep it small.** Change only what the issue needs.
6. **AI tools.** You may use them to understand code and errors. You must
   understand and be able to explain every line you submit.
